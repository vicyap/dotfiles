# Pattern Index

Load only the references needed for the current problem.

## Start From The Problem

- Understand audience, goals, interruption, learning, or repeated work: read
  [Foundations](foundations.md).
- Organize content, workflows, workspaces, settings, search, or help: read
  [Information Architecture](information-architecture.md).
- Help people enter, move, orient, return, or share a location: read
  [Navigation](navigation.md).
- Arrange a screen, establish hierarchy, or manage density and disclosure: read
  [Layout](layout.md).
- Improve composition, typography, color, imagery, accessibility, or tone: read
  [Visual Style](visual-style.md).
- Adapt a task to small screens, touch, context, or intermittent attention: read
  [Mobile and Responsive](mobile-responsive.md).
- Display, browse, select, compare, or add items in a collection: read
  [Lists and Collections](lists-collections.md).
- Present commands, previews, progress, cancellation, undo, or automation: read
  [Actions and Feedback](actions-feedback.md).
- Make complex data explorable and comparable: read [Complex Data](complex-data.md).
- Collect, constrain, suggest, validate, or correct input: read
  [Forms and Controls](forms-controls.md).
- Create or evolve reusable components and interface conventions: read
  [Design Systems](design-systems.md).
- Design connected, anticipatory, assistive, or natural interactions: read
  [Beyond the Screen](beyond-screen.md).

## Common Combinations

- Search or browse experience: information architecture + navigation + lists.
- Checkout, onboarding, or setup flow: foundations + navigation + forms + actions.
- Responsive application shell: information architecture + navigation + layout + mobile.
- Dashboard or analytics workspace: information architecture + layout + complex data.
- Media or asset manager: information architecture + lists + actions.
- Settings: information architecture + forms + actions.
- Design-system work: visual style + actions + forms + design systems.

## Pattern Selection Questions

For each candidate pattern ask:

1. What user problem does it solve here?
2. What evidence shows that problem exists?
3. What new cost, hidden state, or navigation burden does it add?
4. Does the platform already provide a more familiar convention?
5. Can the result be operated and understood without pointer precision, color,
   animation, or memory of a previous screen?
