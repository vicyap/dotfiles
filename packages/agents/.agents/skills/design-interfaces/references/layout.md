# Layout Of Screen Elements

Create a visual hierarchy that matches task priority. Use size, contrast,
position, spacing, alignment, and grouping consistently. Apply proximity,
similarity, continuity, and closure to express relationships. Direct visual flow
through the primary task, keep dynamic changes spatially stable, and divide the
screen into recognizable regions.

Use responsive enabling to reveal controls when they become relevant and
progressive disclosure to postpone complexity. Do not hide frequent actions or
information required to understand a decision.

## Patterns

### Visual Framework
Give related screens a stable shell, region structure, spacing rhythm, and
navigation placement. Let content vary inside the framework without moving
routine controls unpredictably.

### Center Stage
Give the main object or work surface most of the available space and subordinate
supporting controls. Use when one item or activity dominates the user's attention.

### Grid Of Equals
Arrange peer items with comparable visual weight for scanning and selection.
Keep alignment and item boundaries clear; introduce ranking only when the data
supports it.

### Titled Sections
Divide a long or heterogeneous screen into named, visually distinct groups.
Choose labels that predict content and avoid excessive boxes or headings that
fragment a simple page.

### Module Tabs
Switch among a small set of peer sections within one stable context. Keep the
active tab obvious, preserve state sensibly, and do not use tabs for ordered steps
or unrelated destinations.

### Accordion
Let people expand one or several sections in place when headings are enough to
choose what to inspect. Preserve keyboard semantics and avoid hiding information
that must be compared simultaneously.

### Collapsible Panels
Allow optional supporting regions to yield space while keeping their existence
visible. Remember state only when that helps repeated work and provide a clear
restore control.

### Movable Panels
Allow experts to rearrange persistent work regions when workflows truly vary.
Provide defaults, constraints, reset, keyboard alternatives, and durable state;
avoid customization that merely transfers layout work to users.

## Review Checklist

- Does visual importance match task importance?
- Do grouping and alignment communicate the intended relationships?
- Does disclosure reduce complexity without hiding required context?
- Do dynamic changes avoid layout shifts and lost focus?
- Can the layout reflow without changing the task model?
